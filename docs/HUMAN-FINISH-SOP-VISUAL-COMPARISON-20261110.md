# Human Finish — SOP: Side-by-Side Visual Comparison Critique

Added 2026-11-10 at Scott's direct order, from the first day of live use: "when you make them you can take side by side image comparisons to use to help improve the system even more judging and critiquing and asking why and how to improve and why and how."

## The rule

Every Human Finish change that alters anything a user can see ships with a side-by-side comparison: baseline and candidate, same route, same viewport, same state, same content, captured from the actual built or live sites — never from mockups, never from memory. No visual change is reported as an improvement without its comparison attached.

## The critique loop

A comparison is not a trophy. For each pair, the reviewer works the loop in writing:

1. **What is different** — named elements only, observed, not vibes.
2. **Why is it different** — trace each difference to the change that caused it. A difference with no cause is a regression until explained.
3. **Is it better, and why** — judged against the project's intent charter: the person's job, the brand's point of view, the moment of use. "Cleaner" is not a reason. A difference that cannot be tied to the charter is not an improvement, however tidy it looks.
4. **How could it be better still** — the next concrete change the comparison itself suggests, with the charter reason.
5. **Why that change, and how would we know** — the acceptance evidence the next comparison must show.

Repeat steps 3–5 until the honest answer to "how could it be better still" is a P3 detail or an evidence gap that needs a real user, not another opinion.

## Banking

Comparison pairs and their critique loops are evidence artifacts: they are stored with the job's result file, and any pattern that survives the loop — a defect class, a role confusion, a charter violation — is banked into the lesson ledger under Skill step 13, so the next project starts smarter. The system improves because the comparisons accumulate, not because any single verdict was confident.

## Limits

- A side-by-side judges what is visible in the captured state. It says nothing about comprehension, task success, or conversion; those still need the Skill's human evidence. A beautiful pair with no user evidence is INFERRED, never PROVEN.
- Identical conditions or the pair is void: different viewport, content, or state between captures invalidates the comparison and it gets retaken, not explained away.
